## Первый запуск

Для работы нужен Python 3.11 или новее. Если устанавливаете его сейчас, возьмите Python 3.12. Откройте терминал в корне репозитория - в папке, где лежат `Makefile`, `data/` и `solution/`. Интернет нужен для установки библиотек, скачивания выгрузки и отображения подложки карты.

### macOS и Linux

**1. Установите библиотеки.**

```bash
make install
```

Команда создаст окружение `.venv` и установит зависимости. Если на компьютере несколько версий Python, можно выбрать нужную: `make install PYTHON=python3.12`.

**2. Узнайте регион и скачайте его выгрузку.**

```bash
.venv/bin/python data/assign_region.py YOUR_GITHUB_USERNAME
```

Замените `YOUR_GITHUB_USERNAME` своим GitHub username. Скрипт напечатает регион; скачайте его файл по [инструкции к данным](../data/README.md).

**3. Импортируйте скачанный файл.**

```bash
.venv/bin/python data/import_data.py "/path/to/region.geojson.zip"
```

Замените путь своим. Поддерживаются ZIP, GeoJSON и JSON. После успешного импорта появится сообщение `Данные готовы: …`, а выгрузка будет лежать в `data/raw/`.

**4. Запустите приложение.**

```bash
make run
```

Откройте адрес из терминала. На экране должны появиться выбор выгрузки, фильтры и вкладки с динамикой, картой и исходными записями. Остановить сервер можно сочетанием **Ctrl+C**.

### Если make не установлен

Вместо `make install` выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r solution/requirements.txt
```

После получения и импорта данных вместо `make run` выполните:

```bash
.venv/bin/python -m streamlit run solution/app.py
```

### Windows - PowerShell

Сначала создайте окружение и узнайте регион:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r solution\requirements.txt
.\.venv\Scripts\python.exe data\assign_region.py YOUR_GITHUB_USERNAME
```

Скачайте свой регион по [инструкции к данным](../data/README.md), затем импортируйте его и запустите приложение:

```powershell
.\.venv\Scripts\python.exe data\import_data.py "C:\Downloads\region.geojson.zip"
.\.venv\Scripts\python.exe -m streamlit run solution\app.py
```

В этих командах уже указан Python из `.venv`, поэтому отдельно активировать окружение не нужно.

## Как устроен каркас

```text
Данные из data/raw/
        ↓
load_records → исходные записи JSON
        ↓
records_to_frame → таблица выбранных полей
        ↓
фильтры периода, территории и типа ДТП
        ↓
временной график · карта · таблица записей
```

Начните с [solution/app.py](../solution/app.py): здесь собраны фильтры, графики, карта и просмотр записей. Чтение JSON и формирование таблицы вынесены в [data_loading.py](../solution/data_loading.py).

Результаты исследования записывайте в [analysis.md](../solution/analysis.md), а зависимости добавляйте в [requirements.txt](../solution/requirements.txt).

В папке `data/` находятся два вспомогательных скрипта: [assign_region.py](../data/assign_region.py) назначает регион, [import_data.py](../data/import_data.py) копирует выгрузку в проект и записывает сведения о файле в `.source.json`.

### Что важно знать о загрузке

Перед анализом посмотрите, как загрузчик обращается с данными:

- Дубликаты сохраняются. Количество записей и количество уникальных непустых ID показаны отдельно.
- Нераспознанные даты отмечаются и исключаются из фильтра по периоду. Исходный текст остаётся в `datetime_raw`.
- Участники и транспорт остаются во вложенном JSON. Полную запись можно открыть во вкладке «Исходные записи».
- Для карты сначала берутся координаты GeoJSON Point; при отсутствии подходящей структуры используется `properties.point`.
- Проверка `map_valid` учитывает числовые пределы широты и долготы и исключает `(0, 0)`. Она не проверяет принадлежность точки региону.

Если для карты подходит больше 5 000 точек, приложение выбирает 5 000 случайных точек с фиксированным seed и показывает предупреждение. Карточки, временной график и CSV используют все отфильтрованные записи. В таблице на экране видны первые 500 строк.

### Где продолжать работу

Добавляйте графики в `app.py`. Когда файл станет большим, выносите расчёты и графики в модули. Приложение по-прежнему должно запускаться через `solution/app.py`.

Тесты и проекции можно посчитать заранее. Подпишите рядом выборку и параметры расчёта, чтобы их не путали с результатами текущего фильтра. Экспорт, просмотр записей и сброс фильтров уже есть в каркасе; оставьте то, что пригодится в вашем дашборде.

## Зависимости и воспроизводимость

Основной список библиотек - [requirements.txt](../solution/requirements.txt). Добавляйте в него зависимости своего решения.

В [requirements-tested.txt](../solution/requirements-tested.txt) записаны версии библиотек, с которыми мы проверяли каркас на Python 3.12. Чтобы установить те же версии, выполните:

```bash
.venv/bin/python -m pip install -r solution/requirements-tested.txt
```

На Windows используйте `.\.venv\Scripts\python.exe` вместо `.venv/bin/python`. Версии, с которыми вы выполнили работу, запишите в отчёте.

## Если что-то не работает

### Не найден make или Python-модуль

Если `make` не установлен, используйте [команды без make](#если-make-не-установлен). При ошибке `No module named …` установите зависимости через Python из того же `.venv`, которым запускаете приложение.

### Приложение не видит данные

Проверьте, что JSON/GeoJSON находится в `data/raw/`. Один ZIP в этой папке не читается - сначала передайте его импортёру.

Если импортёр сообщает о нескольких JSON в архиве, распакуйте его и передайте нужный файл отдельно. Если уже существует другая выгрузка с тем же именем, переименуйте сам JSON/GeoJSON. Переименование ZIP не меняет имя файла внутри.

### Выбранный срез пуст

Измените период или категорию. В каркасе есть кнопка сброса фильтров.

### На карте нет подложки

Проверьте интернет или выключите «Показывать подложку карты». Точки останутся доступны.

### Порт занят

Укажите другой порт при запуске:

```bash
.venv/bin/python -m streamlit run solution/app.py --server.port 8502
```

На Windows замените путь к Python на `.\.venv\Scripts\python.exe`.
